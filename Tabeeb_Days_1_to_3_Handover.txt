1. EXECUTIVE SUMMARY & COMMITMENT
--------------------------------------------------------------------------------
All release blockers and architectural defects identified in the 11 October 2026
review (Findings A through J) have been investigated, reproduced, and systematically
resolved in priority order.

Key architectural fixes implemented:
- Environment Isolation: Staging deployment workflow strictly targets isolated
  sub-environment (public_html/staging, staging.tabeebgroup.com) with fatal abort
  guards preventing any release to production.
- Fresh & Upgrade Migrations: Corrected illegal ENUM status in fresh migration 002
  and authored additive versioned migration 003 (003_upgrade_idempotency_and_baseline_rbac.sql)
  allowing previously migrated databases to gain the new columns, indexes, and RBAC
  reconciliations without schema resets or data loss.

  seed JSON sources, while excluding client originals at their true path
  (images/client-media/*).
- Lead Submission Idempotency: Replaced bucketed keys with cryptographic random
  submission identifiers bound to payload content hashes. Unchanged retries replay
  cleanly; modified payloads reuse safely or reject conflicts; distinct submissions
  from the same phone/service create separate leads.
- Mailer Resilience & Fenced Workers: Unconfigured SMTP in production returns
  config_blocked without consuming retry budgets. Outbox claiming uses worker lease
  tokens with fenced updates, and PHPMailer timeout is bounded to 15s.

  period (2026-09-12 to 2026-10-09). Unmeasured data is honestly flagged as 'Not available'
  or 'Not previously tracked' rather than fabricating a fake 0, and numeric 0 is

  and percentage savings from JSON fallbacks and templates. Replaced all www URLs with

FINDING A — Staging deployment still writes to production
Resolution:
- Configured dynamic parameterization in .github/workflows/deploy.yml based on target_env:
  * staging -> TARGET_DOC_ROOT="public_html/staging", TARGET_ORIGIN="https://staging.tabeebgroup.com"
  * production -> TARGET_DOC_ROOT="public_html", TARGET_ORIGIN="https://tabeebgroup.com"
- Added fatal safeguard: If TARGET_ENV is 'staging' and either TARGET_ORIGIN resolves to
  tabeebgroup.com or TARGET_DOC_ROOT resolves to public_html or root, the workflow immediately
  aborts with exit 1.
- Upload, extraction, cleanup, and smoke checks now use $TARGET_DOC_ROOT and $TARGET_ORIGIN.

FINDING B — Fresh migration contains a status outside its ENUM
Resolution:
- In config/migrations/002_repair_core_and_projects.sql, the gsc_prefix seed previously attempted
  to insert 'Verification file present on server (Account verification pending)' into status.
- Under strict MySQL (STRICT_TRANS_TABLES), this produced Error 1265 (Data truncated).
- Corrected status to declared ENUM value 'Verification pending' and relocated the full context
  sentence to the evidence_summary column.

FINDING C — Previously migrated databases skip the new repairs
Resolution:
- Authored versioned additive migration config/migrations/003_upgrade_idempotency_and_baseline_rbac.sql.
- scripts/migrate.php records applied migrations in schema_migrations. Databases that ran 002
  will now detect and execute 003 without wiping migration history.
- 003 uses information_schema checks to conditionally add leads.idempotency_key, adds worker_token
  to notification_outbox, updates notification_logs enum, ensures unique index on project_media,
  inserts Serangoon media without touching IDs 1..5, explicitly revokes baseline.manage from
  Role 6 (Analyst), and reconciles gsc_prefix status.

FINDING D — Release package omits SQL required by migrator
Resolution:
- In .github/workflows/deploy.yml, removed exclusion -x "*.sql" and replaced broad -x "data/*"
  with targeted exclusions of temporary/runtime files:
  -x "data/backup_*" -x "data/leads_queue.json" -x "data/*.sqlite*" -x "data/.secret_key"
- Release package now includes config/schema.sql, config/migrations/*.sql, and seed JSONs

  X-Robots-Tag: noindex, nofollow, noarchive on staging.
- Post-deploy smoke check fails fatally (exit 1) on non-200 HTTP response or missing brand content.

FINDING E — Two different enquiries can be collapsed into one
Resolution:
- In app.js, replaced deterministic client_phone_service_bucket key with opaque random
  cryptographic request token (req_<timestamp>_<hex>).
- The token is retained during retry attempts of the same form submission and reset to null
  upon successful 200 response or 409 conflict.
- In api/leads.php, if client key is omitted, server generates unique srv_<token> preventing collisions.
- When an idempotency_key matches an existing database lead:
  * Computes SHA-256 hash of incoming payload (phone, service, message).
  * If hash matches existing lead -> returns 200 OK replay with is_duplicate: true.
  * If hash differs -> rejects with HTTP 409 Conflict (code: IDEMPOTENCY_CONFLICT).
- Two distinct enquiries from the same phone and service within 10 minutes receive different keys
  and are saved as two separate leads.

FINDING F — Missing SMTP consumes retries; worker leases remain incomplete
Resolution:
- In includes/mailer.php, when credentials are unconfigured in production, sendEmail returns
  config_blocked: true.
- In processOutboxQueue(), when config_blocked is true, attempts is NOT incremented; status is
  reset to queued with a 5-minute delayed next_retry_at, preserving the retry budget for when
  credentials are configured.
- Implemented worker lease ownership: Outbox claiming generates worker_token. Status updates
  require WHERE id = ? AND worker_token = ?, preventing expired/stale workers from overwriting
  active claims.
- Bounded PHPMailer transport timeout to 15 seconds ($mail->Timeout = 15).
- Added Mailer::requeuePendingOrFailed($maxAgeHours) for controlled admin requeue.
- Documented private recipient routing: each outbox record is an independent message; internal
  recipients are not exposed in CC/BCC headers.

FINDING G — Project-media seed can overwrite unrelated media rows
Resolution:
- In config/migrations/002_repair_core_and_projects.sql, removed hardcoded primary keys (1..5)

- In config/migrations/003_upgrade_idempotency_and_baseline_rbac.sql, media rows use

- Pre-existing media rows with IDs 1..5 belonging to other projects remain untouched.
- In scripts/migrate.php, project media import is now idempotent and resumable for existing
  projects with partial galleries.

FINDING H — Hardcoded HMAC fallback still exists
Resolution:
- In config/config.php, removed hardcoded fallback secret 'tabeeb_default_secret_key_change_me'.
- In production (APP_ENV === 'production'), if HMAC_SECRET environment variable is missing or
